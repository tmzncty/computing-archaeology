# Source Ledger

This file tracks high-value source collections that support current and future excavations. It is a research map, not a substitute for article-level citations.

The repository prefers primary engineering documents and well-provenanced archival material wherever possible. A link appearing here does **not** mean every statement on that page should be accepted uncritically.

### CDC 6600 design material

- James E. Thornton, *Design of a Computer: The Control Data 6600*, 1970: https://archive.computerhistory.org/resources/text/CDC/cdc.6600.thornton.design_of_a_computer_the_control_data_6600.1970.102630394.pdf

Thornton was deeply involved in the 6600 design. This book is unusually valuable because it records an explicit rationale for the 60-bit operand word: instruction packing and floating-point precision, while address/index registers remained 18 bits.

Source type: designer-authored technical retrospective close to the system's engineering tradition, stronger for design rationale than later folklore but still not a contemporaneous lab notebook.

### IBM 650 primary documentation

The 650 is a major source for understanding what happens when memory latency has physical rotational geometry.

- IBM, *650 Magnetic Drum Data Processing Machine*, 1955 brochure, CHM scan: https://s3data.computerhistory.org/brochures/ibm.650.1955.102646125.pdf
- IBM, *Reference Manual: SOAP II for the IBM 650 Data Processing System*, 1957, Bitsavers: https://www.bitsavers.org/pdf/ibm/650/24-4000-0_SOAPII.pdf
- IBM 650 Program Library, SOAP abstract: https://bitsavers.computerhistory.org/pdf/ibm/650/programLibrary/Additional_Abstracts_of_IBM_650_Programs_Mar57.pdf
- Richard V. Andree, *Programming the IBM 650 Magnetic Drum Computer and Data-Processing Machine*, 1958: https://bitsavers.computerhistory.org/pdf/ibm/650/Andree_Programming_the_IBM_650_Magnetic_Drum_Computer_and_Data-Processing_Machine_1958.pdf

The 1955 brochure documents 12,500 rpm rotation, 50 locations per band, the 2,000-word standard drum, and the instruction's explicit next-instruction address. SOAP material demonstrates that physical drum placement was a software/assembler optimization problem.

### IBM 704 primary documentation

- IBM, *704 Electronic Data-Processing Machine Manual of Operation*, Form 24-6661-2, 1955: https://bitsavers.org/pdf/ibm/704/24-6661-2_704_Manual_1955.pdf

Use for the 36-bit word, core-memory organization, instruction formats, binary arithmetic, and six-character-per-word BCD representation.

### System/360 and descendant architecture

- IBM System/360 history: https://www.ibm.com/history/system-360
- IBM, *z/Architecture Principles of Operation* (descendant architecture; useful for inherited byte/word definitions): https://www.ibm.com/docs/en/module_1678991624569/pdf/SA22-7832-14.pdf?cp=HW11W

The modern z/Architecture manual is not a substitute for the original 1964 System/360 Principles of Operation when making claims about the initial design process. It is useful for documenting the durable architectural lineage: byte-addressed storage, 8-bit bytes, 4-byte words, and related conventions.

## ENIAC / EDVAC / stored-program transition

### First Draft of a Report on the EDVAC

- John von Neumann, *First Draft of a Report on the EDVAC*, 30 June 1945, Smithsonian Libraries digital edition: https://library.si.edu/digital-library/book/firstdraftofrepo00vonn
- CHM-hosted scan: https://archive.computerhistory.org/resources/text/Knuth_Don_X4100/PDF_index/k-8-pdf/k-8-u2593-Draft-EDVAC.pdf

Treat authorship and invention as separate questions. The report circulated under von Neumann's name and was extremely influential; the design environment and underlying ideas involved a broader ENIAC/EDVAC community.

## Bitsavers and manual preservation

https://bitsavers.org/

Bitsavers is essential infrastructure for this repository. It preserves manufacturer manuals, program-library documents, brochures, listings, schematics, training material, and other records that are often absent from modern corporate websites.

It should normally be cited as the **preservation host**, while the document's original author, manufacturer, title, form number, and date remain the bibliographic source.

Current examples used in the repository include IBM 650 SOAP documentation, the IBM 704 manual, and numerous candidate manuals for future work.

## Source-handling rule

For every source ask:

1. Who created it?
2. When?
3. For what purpose?
4. What did the creator know firsthand?
5. What incentives or institutional interests shaped it?
6. Is the page a primary document, institutional synthesis, oral history, retrospective, reconstruction, or tertiary summary?
7. Does another independent source corroborate a strong claim?
8. If the source is a later preservation host, who created the original document?
9. If the claim says “first,” what exact criterion is being used?

A source ledger is useful only if it makes future claims easier to audit.
